# autoparty

B2C-сервис **поиска** автомобильных запчастей в Кыргызстане. Это агрегатор запросов, **не магазин**: клиент платит только за поиск, продавцы отвечают по наличию и цене, клиент сам выбирает, у кого забирать деталь. Покупка, доставка и гарантия детали — вне продукта.

**QR и оплата — демо.** Банк (О!Банк) не подключён.

Интерфейс **светлый**, с высоким контрастом: сервис рассчитан на улицу и на людей постарше. Языки: **русский / English / кыргызча** (переключатель в шапке).

## Стек

- Frontend: React 18 + Vite, Google Maps, i18n в `frontend/src/i18n/messages.js`
- Backend: FastAPI
- Database: PostgreSQL 16
- Realtime: WebSocket (`/api/ws`)
- Запуск: Docker Compose → nginx:80 проксирует `/api/` на backend

```text
browser → nginx :80 → FastAPI :8000 → PostgreSQL
                    ↘ volume uploads
                    ↘ WebSocket hub
```

## Запуск

На сервере (IP `3.75.225.249`) и локально одно и то же:

```bash
docker compose up --build -d
```

Боевой сайт: http://3.75.225.249  
OpenAPI: http://3.75.225.249/api/docs  

Настройки в корневом `.env` (файл **в репозитории**): `PUBLIC_URL=http://3.75.225.249`. QR демо-оплаты собирается из этого адреса. Compose читает `.env` сам — отдельно ничего экспортировать не нужно.

Порт **80** должен быть открыт на машине. После смены `VITE_GOOGLE_MAPS_API_KEY` — снова `--build`.

Первый старт: Postgres → `alembic upgrade head` → идемпотентный `python -m app.seed` → uvicorn. Повторный seed не плодит дубликаты. Колонки/таблицы поверх старого volume дотягивает `backend/app/schema_upgrade.py` (вызывается и из alembic, и при старте API).

Пересборка после правок фронта обязательна: nginx отдаёт собранный `dist`. Карта на Google Maps: ключ `VITE_GOOGLE_MAPS_API_KEY` из `.env` в корне (см. `.env.example`). После смены ключа — снова `--build`.

## Как этим пользуются сейчас

### Клиент

1. **Главная `/`** — дашборд карточек, **не** полноэкранная карта: карта, заказы, счётчики (успешные поиски, авто в гараже), CTA «Давайте начнём».
2. CTA ведёт на **`/search`** (гость — на `/login`).
3. На поиске: свободный текст детали, гараж (одно или несколько авто = несколько заказов), города. Геолокацию браузер **не** спрашивает сам; кнопка «Мой город» опциональна. Без гео город по умолчанию — **Бишкек**.
4. Один платёж **200 KGS** на batch: `POST /api/orders/batch`. Несколько авто → несколько заказов, оплата на первом.
5. Demo-QR → заказ `PAID` → `SEARCHING`, запросы уходят продавцам.
6. Ответы YES / PARTIAL видны в заказе и на **карте `/map`**. Клиент выбирает продавца, пишет в чат, ставит звёзды. Выбор продавца считается исполнением (даже без оценки).

Карта **не** для оформления поиска. На ней: точки, которые ответили «есть» / «частично», и **партнёры** (видны и без заказов, в том числе гостю). HUD поверх карты, нижнее меню карту не перекрывает.

### Продавец

Вкладка **Запросы** `/seller`. Ответ по позициям: есть / нет / частично, цена, новое/б/у, оригинал, комментарий. Честный «нет» активность не штрафует. Своя точка на карте + контакты (адрес, WhatsApp / Telegram / Instagram).

### Админ

`/admin`: дашборд, пользователи, продавцы (апрув, партнёрство 1–5, страйки), очередь жалоб, ложные YES, ротация, заказы, платежи, чаты, категории, города, audit.

Кнопка «Стать продавцом» — внешняя заглушка. Апрув продавца вручную.

## Геолокация и карта

- `navigator.geolocation` вызывается **только** по кнопке «Мой город» на `/search`.
- Сайт полностью работает без разрешения. Карта без гео центрируется на Бишкеке `[42.8746, 74.5698]`.
- Карта: Google Maps (`VITE_GOOGLE_MAPS_API_KEY`). На главной карта не грузится — там статичная карточка-превью.
- `GET /api/map/points`: гости — партнёры; клиент — свои офферы YES/PARTIAL + партнёры; продавец — своя точка + партнёры.
- `GET /api/locations/nearest?lat=&lng=` — ближайший город из сида (~30 городов КР с координатами и радиусом поиска).

## Распределение запросов

После demo-оплаты:

```text
заказ
 → matching: APPROVED ∩ город ∩ категория
 → без страйк-бана на новые заказы
 → quality score → базовая задержка
 → мягкая ротация (пока выключена при малом объёме)
 → партнёры: без ротации, короче задержка
```

Задержку в демо крутит in-process scheduler (asyncio/thread). Очереди задач нет.

**Quality score 0–100** (`backend/app/services/scoring.py`):

```text
0.40 рейтинг (display_rating)
0.12 уверенность (число оценок)
0.20 доля ответов          # «Нет» тоже ответ
0.08 скорость
0.12 опыт (исполненные)
+ партнёр: уровень × 4
− жалобы / ложные YES
```

Пороги задержки из env: ≥70 → 0 с, ≥40 → 10 с, иначе 30 с.

**Ротация** (`platform_settings`, вкладка админки): пока оплаченных поисков меньше `rotation_after_orders` (**по умолчанию 20**), все подходящие продавцы получают запрос сразу. После порога тем, кто недавно много получал, добавляется задержка (партнёры исключены).

**Display rating** (звёзды в карточке): байесовский приор 4.2 / 2 оценки + бонус за исполненные − штраф за подтверждённые жалобы и ложные YES.

**Жалобы и страйки:** WRONG_PART / FALSE_AVAILABILITY / OTHER. 3 подтверждённых жалобы → блок **новых** заказов ~30 дней. Уже назначенные запросы продавец продолжает видеть.

## Demo payment

1. Заказ `WAITING_FOR_PAYMENT`, цена `SEARCH_PRICE_KGS` (200).
2. `POST /api/payments/demo/create` → QR.
3. Скан `/api/payments/demo/{token}/scan` помечает `PAID` и редиректит на Rickroll-заглушку.
4. На экране оплаты есть «Имитировать callback» — когда телефон не достучится до `localhost`.

Это **не** О!Банк.

## Роли

- **CLIENT** — гараж, batch-поиск, оплата, офферы, карта, чат, выбор продавца, оценка, жалоба.
- **SELLER** — входящие запросы, оффер YES/NO/PARTIAL, чат, публичная точка.
- **ADMIN** — модерация и настройки платформы.

## API

- `/api/auth` — регистрация, JWT
- `/api/profile` — профиль, заказы за 3 месяца, чаты
- `/api/garage` — автомобили клиента
- `/api/orders` — один заказ или `POST /batch`, выбор продавца, complete/cancel
- `/api/payments/demo/*` — demo QR / callback
- `/api/seller` — профиль, запросы, офферы, фото позиции
- `/api/chats`, `/api/chats/unread-count`, сообщения
- `/api/map/points`
- `/api/locations`, `/api/locations/nearest`, категории, бренды, popular parts
- `/api/reports` — жалобы; админ: очередь и false-answers
- `/api/ratings`
- `/api/notifications`, `/api/ws`
- `/api/admin`, `/api/admin/rotation`, `/api/admin/audit-logs`
- `/api/health`, `/api/media/{filename}`

Локализация каталога: `Accept-Language` или `?lang=` (`ru` / `en` / `ky`). Каноническое `name` в БД — русский, рядом `name_en` / `name_ky`.

Новые пользовательские строки сразу в трёх локалях — правило `.cursor/rules/i18n-ru-en-ky.mdc`.

## База

Пользователи и продавцы: `User`, `SellerProfile` (координаты, мессенджеры, страйки, партнёрство, display_rating).  
Гео: `Country` / `Region` / `City` (lat/lng, `search_radius_km`).  
Клиент: `UserVehicle` (гараж).  
Заказ: `Order`, `OrderItem`, `OrderLocation`, `Payment` (`batch_id` на пачке).  
Распределение: `OrderSellerAssignment`, `SellerOffer`, `SellerOfferItem` (availability, price, condition, original, detail).  
Коммуникации: `Chat`, `ChatParticipant.last_read_at`, `Message`, `Notification`.  
Доверие: `Rating`, `Report`, `PlatformSettings`.  
Прочее: категории, бренды/модели, popular parts, `AuditLog`.

## Что сознательно не сделано

- О!Банк / реальная оплата
- Подтверждение телефона (Telegram-код)
- Настоящая регистрация продавца
- S3 вместо volume
- Очередь задач вместо in-process delay
- AI, VIN, SMS/email/push
- Тёмная тема
